# C4 / logical architecture

LikeC4 is the C4 model. Elements nest. Views project.

## Completion

Done when a named `view` (or `view of <element>`) shows the asked boundary and every relationship on that picture exists in `model { }`.

## Write

1. Kinds in `specification` (`actor`, `system`, `service`, `component`, `database`, `queue`). Reuse `model/spec.c4`. Add a kind only when an existing one is the wrong noun.
2. Hierarchy in `model`: actor / external system at the top, then `system` → `service` → `component`. Datastores are `database` with `shape storage`.
3. Relationships at the leaf that actually talks (`panel.api -> datastore.pg`), not only at the parent. Parent-to-parent edges are inferred on `include *`.
4. Views:

   ```
   view index { include * }
   view containers of promise { include * }
   view panel_zoom of promise.panel { include *; include * -> * }
   ```

## Style

- `shape person` on actors, `shape browser` on UI, `shape storage` on datastores, `shape queue` on Kafka.
- Bundled icons: `icon tech:nginx`, `tech:postgresql`, `tech:redis`, `tech:apache-kafka`, `tech:kubernetes`.
- Title and one-line `description` on anything the user will click.

## Do not

- Flatten the landscape into one `service` per VM. VMs belong in [network.md](network.md).
- Duplicate a service under two parents. Reference it once; deploy it with `instanceOf`.
